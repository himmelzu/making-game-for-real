# ID 2002079023 사진 한 장 시험하기

사진 파일 하나를 복사해 이름을 바꾸면 됩니다. XML 내용은 직접 편집하지 않아도 됩니다. `index.html`을 먼저 열었는지, `face.html`을 바로 열었는지는 이 문제의 원인이 아닙니다.

[전용 ZIP 다운로드](https://github.com/himmelzu/making-game-for-real/raw/refs/heads/main/downloads/fm26-probe-2002079023.zip)

1. **FM26을 완전히 종료합니다.** 기존 `graphics\new` 안의 `faces\face_0001.png`를 바탕 화면 같은 곳에 복사해 둡니다. 기존 `new` 폴더는 `graphics` **밖**으로 옮겨 보관합니다. 같은 ID의 이전 config가 함께 읽히는 것을 피하기 위한 조치입니다. 기존 `graphics\faces\celeb` 폴더는 그대로 둡니다.
2. ZIP을 풀면 `fm26-probe-2002079023` 폴더와 그 안의 `config.xml`이 나옵니다. 이 폴더를 아래 `graphics` 폴더 안에 넣습니다.
3. 복사해 둔 사진을 **config.xml 바로 옆**에 넣고, 사진 이름을 **`fm26_probe_2002079023.png`**로 바꿉니다. `faces` 하위 폴더에 넣지 않습니다. 탐색기의 **보기 → 표시 → 파일 확장명**을 켜 두면 `.png.png`로 중복되는 실수를 피할 수 있습니다. 사진은 원래 PNG 파일을 사용하고, JPG 파일의 확장자만 바꾸지 마세요.
4. FM26을 다시 실행해 **ID 2002079023** 선수의 사진을 확인합니다. 다른 선수에게 이 config를 쓰면 안 됩니다.

최종 배치는 다음과 같습니다. ZIP의 안내 TXT 파일은 남아 있어도 됩니다.

```text
C:\Users\himme\Documents\Sports Interactive\Football Manager 26\graphics\
└─ fm26-probe-2002079023\
   ├─ config.xml
   └─ fm26_probe_2002079023.png
```

ZIP에는 사진이 들어 있지 않습니다. 사진은 사용자가 선택했던 원본 한 장을 복사합니다. `config.xml`은 `r-2002079023`과 숫자 `2002079023` 두 경로를 같은 사진에 연결합니다. 이 선수는 새 게임 시작부터 있었으므로 생성 선수인지 기본 DB 선수인지 아직 확정하지 못해 **한 ID에 한정해 두 경우를 시험**합니다. 모든 선수의 `r-`를 지우라는 뜻은 아닙니다.

기존 파일 배치는 XML 문법상 일치했습니다. 이번 시험은 고유한 파일명·하위 폴더 없는 배치·두 ID 경로를 사용해 FM26의 경로/선수 종류 관련 변수를 줄입니다. 실제 게임 표시 성공은 아직 확인하지 못했습니다. 사진 연결만 바뀌며 선수 이름·능력치·세이브 데이터는 수정하지 않습니다. 문제가 있으면 이 시험 폴더를 graphics 밖으로 옮기고 보관한 원래 `new` 폴더를 돌려놓을 수 있습니다.
