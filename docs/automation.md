# Windows 자동화 실험판 v3

현재 도구는 게임을 직접 읽어 선수 ID 목록을 만들고, 선택한 후보의 이름 네 항목과 얼굴 연결을 일괄 적용하는 **실험판**입니다. CSV 작성과 선수별 인게임 에디터 입력을 줄이는 실행 코드를 포함했습니다. FM26에서 실제로 실행해 저장·재로드한 검증은 아직 못 했습니다.

**기존 세이브의 별도 사본에서 먼저 확인해야 합니다.** 이름 문자열 참조의 수명·참조 횟수 관리와 게임 저장 후 영속화는 아직 검증되지 않았습니다. 테스트 통과를 게임 호환성 검증으로 설명하지 않습니다.

## 한 번 설정한 뒤 사용하는 흐름

1. ZIP 전체를 새 폴더에 풀고 FM26에서 별도로 저장한 사본을 불러옵니다. 게임을 일시정지합니다.
2. `Start.cmd`를 실행합니다. Python은 공식 Windows용 실행 환경을 함께 넣었으므로 별도 설치하지 않아도 됩니다. 실행 창을 닫으면 도구도 종료됩니다.
3. 브라우저에서 기존 얼굴팩의 `celeb` 폴더와 현재 FM26이 사용하는 `graphics` 폴더를 선택합니다. 새 세이브를 구분할 커리어 이름을 정하고 설정을 저장합니다.
4. **게임 읽기 스캔**을 실행합니다. 가능하면 게임의 현재 날짜도 직접 읽습니다. 날짜를 못 읽었을 때만 게임 화면의 날짜를 입력합니다. PC의 오늘 날짜를 입력하지 마세요.
5. 첫 사용에는 **현재 선수 첫 등록**을 누릅니다. 이 단계는 기준 명단·사진에 대응하는 연예인 이름 제공자·기존 보호 선수만 기록하고 게임을 변경하지 않습니다.
6. **배정 미리보기**에서 후보를 확인합니다. 이미 진행 중인 세이브의 유소년을 바꾸려면 ‘현재 세이브에 이미 있는 14~18세 여성 선수도 후보에 포함’을 선택합니다. 기존 실존 유망주가 섞일 수 있으므로 목록을 확인해야 합니다.
7. 최대 1,000명을 선택하고 일시정지·실험판 안내를 확인한 뒤 **선택한 항목 적용**을 누릅니다. 게임 속 이름 참조를 바꾸고 전용 얼굴팩을 만듭니다. 국적·구단·컵 규칙은 바꾸지 않습니다.
8. 게임의 그래픽/스킨을 새로고침하고 이름과 사진을 확인합니다. **다른 이름으로 저장한 뒤 다시 불러와** 이름과 능력치 유지가 남는지 확인해야 합니다. 이 마지막 게임 검증은 이 클라우드에서 할 수 없었습니다.

다음 유소년 입단 때는 같은 커리어 이름으로 **스캔 → 미리보기 → 선택 → 일괄 적용**하면 됩니다. 매일 켜 놓는 완전 무인 방식이 아닙니다. 적용 뒤에는 이전 스캔의 값이 달라지므로 다음 적용 전에 다시 검사합니다.

## 자동 처리와 남는 작업

| 항목 | 이 실험판이 하는 일 |
| --- | --- |
| 선수 ID 목록 | 실행 중인 게임 메모리에서 읽습니다. CSV를 직접 만들지 않습니다. |
| 새 유소년 후보 | 기준 명단 뒤 처음 보인 14~18세 여성 선수를 찾습니다. 게임의 생성 플래그를 확인한 것은 아닙니다. |
| 이름 | 최초 스캔에서 확인된 기존 연예인 이름의 참조를 사용해 이름 4항목을 한 번에 바꿉니다. 인게임 에디터에 한 명씩 입력하지 않습니다. |
| 사진 | 원본 PNG의 해시를 확인하고 `graphics/fm26_celebrity_auto`에 복사·연결합니다. 같은 사진은 한 번만 복사합니다. |
| 유소년 능력치 | 게임의 원래 CA·PA와 성장 방식을 유지합니다. 일괄 고정하지 않습니다. |
| 기존 보호 선수 | 확인된 연예인에게 native 능력치 고정 비트를 설정하고, 기준 CA·PA보다 낮아진 수치는 기준값까지 보정합니다. |
| 기존 선수 나이 | 보호 선수 중 28세 이상은 게임 날짜 기준 22세가 되도록 생년을 조정합니다. 생일과 날짜의 다른 비트는 보존합니다. |
| 은퇴 | 확정된 은퇴 날짜를 지우지 않습니다. 나이 조정과 능력치 고정이 전체 은퇴 방지 기능이라는 뜻은 아닙니다. |

사진 기본 목록은 자막을 확인한 118장입니다. 동명이인이나 게임 안에서 이름 제공자를 한 명으로 확인하지 못한 항목은 제외합니다. 추가 사진을 구하지 않고 재사용할 수 있습니다. 이 버전은 임의의 새 연예인 이름을 게임에 새로 할당하는 기능이 없으며 **게임에 이미 있는 연예인 이름을 재사용**합니다.

기존 연예인 전체 960명을 무조건 보호하지 않습니다. 원본에서 확인한 771명 중 **실제 게임의 이름·생일 월일·성별이 맞는 사람**만 등록합니다. ID 밀림을 피하려고 XML의 후보 ID나 사진 파일 번호를 실제 ID로 쓰지 않습니다. 기준 선수나 이름 제공자가 5명 미만이면 일괄 적용용 등록을 막습니다.

## 버전과 게임 데이터의 한계

현재 쓰기 허용 후보는 `game_plugin.dll`의 전체 파일 버전 **26.3.0.0 / 26.3.2.0**입니다. 출처가 26.3.0·26.3.2로 설명한 메모리 배치에 한정한 실험적 게이트이며, 이 두 빌드를 우리 쪽에서 실제 게임으로 검증했다는 뜻이 아닙니다. DLL의 SHA-256을 기록하고 다른 바이너리로 바뀌면 기존 커리어 기록의 적용을 중단합니다. 모르는 버전이나 불완전한 스캔·중복 ID에서는 읽기 진단만 하고 쓰기를 차단합니다.

게임이 ‘나중에 로드한 기존 선수’를 새로 발견할 수 있습니다. 처음부터 큰 DB로 로드하고, 후보 목록을 확인해야 합니다. 서로 같은 DB로 만든 다른 세이브는 원래 선수 ID와 random ID가 같을 수 있습니다. **커리어 이름은 게임 세이브 ID를 자동으로 알아낸 값이 아닙니다. 새 세이브·과거 시점의 분기는 새 이름으로 등록하세요.** 모든 세이브 전환을 자동 감지한다고 보장하지 않습니다.

현재 날짜는 `game_plugin.dll`의 명확한 단일 명령 패턴에서 4바이트 날짜를 직접 읽을 때만 자동 사용합니다. 패턴이 없거나 여러 개이거나 날짜가 불안정하면 수동 입력으로 전환합니다. 다음 경기 날짜·PC 날짜·가장 어린 선수 생년으로 날짜를 추정하지 않습니다. 자동으로 읽은 날짜도 처음에는 게임 화면과 비교하세요.

메모리 수정은 원래 게임 문자열 자체를 덮어쓰지 않고 기존 이름 참조를 복사합니다. 별도 전체 이름 항목도 포함합니다. 하지만 원본 연예인이 사라진 뒤 문자열이 계속 유효한지, 이름 변경이 저장·재로드·재실행 뒤에도 남는지는 이 환경에서 검증하지 못했습니다. 정상 작동을 보장하는 완성판으로 사용하면 안 됩니다.

## 기록과 복원

설정·기준 명단·일괄 변경 저널은 `%LOCALAPPDATA%\FM26CelebrityHelper`에 보관합니다. 사진과 게임 데이터는 외부로 전송하지 않습니다. 기존 FMF·세이브 파일을 직접 덮어쓰지 않지만, 적용한 메모리 변경은 나중에 게임을 저장하면 저장될 수 있습니다.

사진은 도구 전용 폴더만 관리하고 이전 팩 1세대를 보관합니다. 원본 사진과 다른 얼굴팩 설정을 고치지 않습니다. 이미 다른 팩에 같은 대상 ID가 있으면 우선순위에 따라 충돌할 수 있습니다. 자동으로 다른 팩을 수정하지 않습니다.

**마지막 적용 되돌리기**는 같은 도구 실행·같은 스캔 세션에서만 가능합니다. 현재 값이 도구가 쓴 값과 일치하는 항목만 복원하고, 사진팩이나 기록이 사용자에 의해 바뀌었으면 중단합니다. 이미 게임을 다시 로드했거나 다시 검사했다면 이전 메모리 주소를 재사용하지 않습니다. 일부 쓰기·디스크 오류가 남으면 별도로 저장한 게임을 복원해야 합니다. JSON 저널과 같은 이름의 `.progress.jsonl`이 있으면 함께 보관하세요.

게임이 안 잡히면 `fm.exe`가 하나만 실행됐는지, 세이브를 완전히 불러왔는지 확인하세요. 게임이 높은 권한으로 실행 중이면 도구와 권한이 다를 수 있습니다. DLL 버전·중복 ID·읽기 오류는 로컬 `last-diagnostic.json`에 기록됩니다. 이 문서는 추가 구매나 다른 편집기 설치를 요구하지 않습니다.
