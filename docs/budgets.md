# 구단 자금 지원 수정

사용자가 확인한 단일 통합 XML을 바탕으로, 상위 리그 구단만 자금으로 우위를 굳히는 상황을 완화하기 위한 변경입니다. 새 게임용 프리게임 데이터이며 기존 세이브에 소급 적용되지 않습니다.

## 적용 범위

- 1~6부 전체 500팀에 리그 기본 참가 지원금 `100,000,000`을 매 시즌 각 팀 지급하도록 설정합니다. 기존에는 1~5부에 1,000,000 / 500,000 / 250,000 / 100,000 / 50,000의 기본 지원금이 있고 6부에는 없었습니다.
- 같은 시즌에 한 팀이 부모 리그와 하위 그룹에서 중복 지원금을 받지 않도록, 기존 1~5부의 지급 경로를 수정하고 6부 한 경로만 추가합니다. 3~5부의 하위 그룹에는 지급 경로를 만들지 않습니다.
- 원본에서 구단 재정 레코드를 직접 확인할 수 있는 연예인 구단 39곳에는 시작 잔액 `100,000,000`, 이적 예산 `50,000,000`, 남은 선수 급료 예산 `1,000,000`을 설정합니다. 최대 개인 급료 제한은 바꾸지 않습니다.
- 성적 상금, 컵 상금, 관중 수입, 후원, 명성은 유지합니다. 이사회 결정, 선수의 이적 선호와 기존 부채도 달라질 수 있으므로 모든 구단이 영구히 같은 재정을 유지한다는 뜻은 아닙니다.

위 숫자는 XML에 저장되는 FM 에디터 금액입니다. 통화 환산과 급료의 표시 주기를 이 환경에서 독립적으로 확인하지 못했으므로, 정확히 몇 파운드·몇 원·주급 얼마로 표시된다고 보장하지 않습니다. 에디터와 게임의 재정 화면에서 확인해야 합니다.

기본 지급일은 **매 시즌 8월 11일**로 설정하고 리그의 `year_interval=1`, `base_year=2000`을 유지합니다. 원본 리그 개막일인 8월 10일 직후로 옮겨, 기존 7월 1일 지급일을 첫 시즌에 놓칠 가능성을 줄였습니다. 특정 요일 조건도 없앴습니다. 게임 시작일이 8월 11일보다 늦으면 첫 시즌 지급 시점은 게임 엔진의 처리에 따라 달라질 수 있습니다. 다음 시즌 반복 지급도 실제 게임으로 확인해야 합니다.

## 왜 모든 구단의 시작 예산을 똑같이 쓰지 않았나요?

원본에서 경기 참가를 나타내는 구단 참조 UID와 재정 변경 기록의 UID가 다르게 기록된 사례가 확인됐습니다. 예를 들어 YG의 재정 기록 키는 `792971584703919109`, 6부 배정 기록 키는 `792971584703919110`입니다. 숫자를 임의로 빼서 실제 구단으로 추정하지 않았습니다.

시작 예산은 기존 재정 필드의 최종 변경 기록을 확인한 39구단만 수정합니다. 전체 500팀에는 개별 UID 변환이 필요 없는 리그의 `each_team` 지급 규칙으로 지원합니다. 따라서 **500팀의 시작 잔액·이적 예산·급료 예산을 모두 동일하게 맞춘 파일이라고 설명하면 안 됩니다.**

전체 참가 수는 최신 1~6부 배정 기록에서 삭제된 9팀을 제외해 확인했습니다. 각 단계는 20 / 20 / 60 / 120 / 240 / 40팀입니다.

## 스키마와 검증 근거

원본에 이미 있는 프리게임 구단 속성을 사용합니다. `Ccba`는 잔액, `Ctbu`는 이적 예산, `Crmb`는 남은 선수 급료 예산입니다. 경기 실행 중 속성인 `Ctfc`·`Cwwb`를 새로 만들어 넣지 않습니다. 속성 이름의 공개 비교 자료: [club.yaml, commit 120ba92](https://github.com/AlessandroCarcangiu/fm-pre-game-massive-editor/blob/120ba92fad9dd586bdf9d2d299c88380bfb4c273/settings/club.yaml).

Python 정적 검사는 117개 기존 재정 필드 변경, 6개 리그 기본 지급 경로, 나머지 모든 선수·구단 변경 기록 및 리그·컵 규칙 보존, 삭제 구단 제외, 중복 지급 경로 차단을 검사합니다. 이 검사는 FM26 Editor의 규칙 검증이나 게임 실행을 대신하지 않습니다.

재현:

```text
python tools/build_budget_patch.py downloads/fm26-unified-data.zip /tmp/FM26_funding_review.xml
python -m unittest discover -s tests -p test_budgets.py
```
