# 유소년 사진 파일이 있는데도 표시되지 않을 때

이전 도우미의 `face_0001.png`는 config가 지정한 임의 파일명이며 그 자체로 잘못된 이름은 아닙니다. `from="faces/face_0001"`과 `faces/face_0001.png`가 맞으면 파일 배치와 XML 문법은 일치합니다. 그 상태에서 표시되지 않는 것을 사용자의 설치 실수로 단정할 수 없습니다.

FM26 커뮤니티에는 [생성 선수 사진의 하위 경로 문제 보고](https://community.sports-interactive.com/forums/topic/594605-regen-faces-fm26/)가 있고, [FM26 사용자 그래픽 안내](https://community.sports-interactive.com/forums/topic/593885-fm26-updates-to-custom-graphics/)에는 모든 사진 파일명을 고유하게 하라는 안내가 있습니다. 모든 FM26 빌드가 하위 경로를 무조건 거부한다는 뜻은 아닙니다. 기존 출력은 게임 내 호환성 검증이 부족했습니다.

새 도우미는 사진을 **config.xml과 같은 폴더**에 넣고, 사진 파일명에 **실제 선수 ID**를 포함합니다. 같은 사진을 여러 선수에게 쓸 때는 이 묶음에서 첫 실제 ID의 파일 한 장을 공유합니다. 서로 다른 실제 ID의 묶음은 같은 `face_0001.png` 이름을 반복하지 않습니다.

```text
graphics/
└─ 새유소년팩/
   ├─ config.xml
   └─ fm26_celeb_2002079023.png
```

```xml
<record from="fm26_celeb_2002079023" to="graphics/pictures/person/r-2002079023/portrait"/>
```

현재 도우미에서 다시 내보낼 수 있습니다. 기존 파일 한 명으로 시험하려면 사진을 config 옆으로 옮겨 `fm26_probe_2002079023.png` 같은 고유 이름을 사용하고, config의 `from`을 `fm26_probe_2002079023`으로 바꿉니다. 위 ID는 사용자가 실제 확인한 유소년 ID의 사례이며 다른 선수에게는 해당 선수의 실제 ID를 사용해야 합니다. `to`의 실제 ID와 `r-`는 그대로 둡니다.

동일 선수 ID를 연결한 이전 도우미 폴더는 graphics **밖**으로 빼고 교체합니다. 현재 게임이 읽는 graphics 위치에서 시험한 뒤 게임을 완전히 종료하고 다시 실행해 확인합니다. 두 config가 같은 ID를 연결하면 어느 것이 보일지 로딩 순서에 의존하게 됩니다. 사진 파일만 바꾸어도 게임 속 이름은 바뀌지 않습니다.

시작부터 존재한 유소년은 기본 DB 선수일 수도 있고 새 게임 시작 시 생성된 선수일 수도 있습니다. 20억대 ID나 어린 나이만으로 종류를 정하지 않습니다. 간단 도우미의 **사진을 연결할 선수 종류**에서 생성 선수는 `r-ID`, 기본 DB 선수는 숫자 ID를 선택할 수 있습니다. 종류가 다른 선수는 나누어 출력하고 실제 표시를 확인해야 합니다. 숫자로 입력한 ID를 도구가 자동으로 기본 DB 선수라고 판단하는 것도 아닙니다.

`web/face.html`의 선택 항목인 **압축을 푼 얼굴팩 폴더 배치 확인**은 사진 누락·잘못된 경로·PNG 헤더와 하위 경로 주의사항을 읽기 전용으로 검사합니다. 파일 경로가 모두 맞다는 결과가 실제 게임의 표시 성공을 증명하지는 않습니다. 실제 FM26 표시 결과는 사용자 게임에서 확인해야 합니다.
